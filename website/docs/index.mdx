# Stardust

Stardust is an independently maintained personal AI assistant built on the open-source **Hermes Agent** codebase. Hermes provides the technical foundation and much of the inherited runtime; Stardust owns the product direction, desktop experience, model-routing behavior, installation/update sources, and ongoing maintenance in this repository.

## Install Stardust

Fresh installations must use Stardust-owned bootstrap entrypoints. Do not use the former Hermes website installer for this project; that installs a different upstream product.

### Linux / macOS / WSL / Termux

```bash
curl -fsSL https://raw.githubusercontent.com/9529360-cpu/stardust-hermes/main/scripts/install-stardust.sh | bash
```

### Windows PowerShell

```powershell
iex (irm https://raw.githubusercontent.com/9529360-cpu/stardust-hermes/main/scripts/install-stardust.ps1)
```

The inherited CLI command is still named `hermes` for compatibility, so setup and runtime examples throughout older documentation may continue to use commands such as:

```bash
hermes setup
hermes --help
hermes desktop
```

That command name is a compatibility interface, not the current product identity.

## Product direction

Stardust is optimized for long-term personal use rather than upstream release parity. Current priorities include:

- a calmer, Chinese-first personal-assistant desktop and navigation model;
- independent desktop layout and visual language rather than preserving the upstream UI;
- persistent health tracking, cooldown/circuit-breaker behavior, and fallback for model routes;
- credential-pool rotation before route-level fallback;
- reliable local and remote Gateway operation;
- Stardust-owned install, recovery, update, packaging, and release paths;
- focused regression coverage for the boundaries that matter to daily use.

## Update and source authority

`9529360-cpu/stardust-hermes` is the source and release authority for Stardust.

Stardust does **not** use periodic upstream merge/rebase or automatic Hermes synchronization as a maintenance strategy. A useful upstream implementation may be studied or manually adapted for a concrete need, but Stardust development continues directly in this repository.

The inherited `hermes update` upstream synchronization path is intentionally disabled. Desktop product update actions must update Stardust Desktop itself and must not silently replace the backend checkout with upstream Hermes source.

## Compatibility boundaries

The codebase still contains many inherited names such as `hermes`, `HERMES_HOME`, `window.hermesDesktop`, package names, executable paths, protocol identifiers, and historical data directories. Some of these are load-bearing compatibility surfaces for existing installs.

Do not mechanically rename them just for branding. A real rename requires migration and rollback behavior plus tests proving existing installations and user data remain usable. New user-facing copy and new ownership/release metadata should use **Stardust**.

## Capabilities inherited from the foundation

The underlying runtime already provides a broad agent platform, including:

- CLI, TUI, Electron desktop, dashboard, and messaging Gateway surfaces;
- tools for terminal, files, browser/web workflows, MCP, and automation;
- persistent memory and reusable skills;
- profiles, scheduled jobs, plugins, providers, and remote execution backends;
- multiple model/provider integrations, including optional external services such as Nous Portal, OpenRouter, OpenAI-compatible endpoints, and others documented in the integration guides.

Stardust may keep, simplify, replace, or extend these capabilities according to personal-assistant needs. The presence of an inherited feature does not require matching upstream product direction.

## Privacy boundary

This source repository must not contain personal runtime data: real credentials, `.env` files, conversations, memories, profiles, logs, route-health state, local databases, backups, or packaged applications carrying local state.

Runtime data remains outside the checkout in the inherited profile-aware data hierarchy.
